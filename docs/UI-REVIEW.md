### 5차 수정 (격자 좌우 균형과 그 뿌리)

마지막 남은 보통 항목 **"참가자 1명일 때 가운데 135pt 빈 띠, 셀은 188×56pt에 한 자리 숫자만"** 을
잡으면서, 그 아래 깔려 있던 문제 네 개가 함께 드러났다.

- **칸 안이 비어 보이던 것** — 예전에는 개수와 개당 점수 중 하나만 보여줬다. 기록이 없으면 `110점`,
  있으면 `4`. 그래서 `110점`을 완등 110개로 읽는 사람이 있었고, 반대로 기록을 남기는 순간
  그 색이 몇 점짜리인지 알 수 없게 됐다. 이제 늘 `4  +110점` 처럼 함께 적는다.
  `+` 를 붙여 "누르면 오르는 값"임을 못 박았고, 칸이 좁으면 두 줄로 접힌다
- **가운데 빈 띠** — 난이도 이름과 칸 사이를 가는 선으로 잇는다. 자리가 남을 때만 그려지고
  여럿이면 폭 0이 되어 저절로 사라진다. 여백을 margin 이 아니라 그러데이션의 투명 구간으로 준
  이유도 같다. margin 은 자리가 없을 때도 폭을 먹어 4명일 때 이름을 `빨…` 로 잘랐다
- **내 레벨 표식이 숫자로 읽히던 것** — 세로 막대가 칸 가운데 높이에 있어 좁은 칸에서는
  숫자 바로 왼쪽에 붙었다. `❙0` 이 `10` 으로 읽혔다. 숫자와 겹칠 수 없는 모서리 점으로 옮김
- **5명일 때 이름이 한 글자로 잘리던 것** — 순위 배지와 이름을 한 줄에 묶어 둔 탓.
  자리가 모자라면 배지가 윗줄로 올라가 이름에 열 폭을 통째로 내주도록 함
- **0점인 사람만 순위 배지가 없던 것** — 그 칸만 모양이 달라졌다. 아무도 기록이 없을 때만 감춘다

### 도구가 1명짜리 화면만 보고 있었다

이 항목들이 여태 안 잡힌 이유는 단순하다. 60장짜리 검토 루프(`review.mjs`)의 시드가 늘 참가자
1명이라, **여럿일 때의 격자는 검토 루프에 한 번도 오르지 않았다.** 열 개수에 따라 폭이 완전히
달라지는 화면인데 한 가지 경우만 본 것이다. 3명·4명을 찍는 일회용 스크립트(`grid-shot.mjs`,
`grid-n.mjs`)가 있긴 했지만 루프 밖이라 최근 변경 뒤로 아무도 다시 돌리지 않았다.

`tools/shot-grid.mjs` 로 둘을 대체한다. 1~5명을 각각, 다크·라이트·좁은화면으로 찍는다.
위 다섯 건 중 네 건은 그 도구를 만들자마자 첫 장에서 나왔다.

### 좀비 브라우저가 검사 결과를 조용히 오염시키고 있었다

`hold-speed.mjs` 가 `Input.dispatchTouchEvent` 에서 15초 타임아웃으로 죽고 있었다.
원인은 앱이 아니라 드라이버였다.

- 스크립트가 중간에 던지면 `close()` 가 실행되지 않아 헤드리스 크롬이 살아남는다.
  확인 시점에 **60개 프로세스가 떠 있었다**
- `cdp.mjs` 는 포트를 `9333 + (순번 % 200)` 으로 정했고 순번은 프로세스마다 0부터 시작한다.
  즉 새 실행은 늘 9333부터 잡으려 든다. 좀비가 그 포트를 물고 있으면 새 크롬은 바인딩에 실패하고,
  드라이버는 `/json/list` 로 **좀비의 탭을 받아 그걸 조종한다**
- 그러면 방금 만든 화면이 아니라 남의 화면을 검사하게 된다. 이번엔 타임아웃으로 드러났지만,
  드러나지 않았다면 "문제 없음" 이라고 보고했을 것이다

고친 방식은 포트를 우리가 고르지 않는 것이다. `--remote-debugging-port=0` 을 주면 크롬이 빈 포트를
잡아 `DevToolsActivePort` 파일에 적어 준다. 거기에 더해 띄운 브라우저를 전부 기억해 두고
`exit`·`SIGINT`·`uncaughtException` 에서 `SIGKILL` 로 정리하고 임시 프로필도 지운다.
`hold-speed.mjs` 는 이제 정상 동작한다 (탭 6번 → 6, 300ms 길게 → 5, 900ms 유지 → 1).

`hold-speed.mjs` 자체에도 같은 부류의 버그가 있었다. `.cell__count` 를 전체에서 4번째로 세는데
그 요소는 기록이 있는 칸에만 생긴다. 4번째 **칸** 안에서 찾도록 고쳤다.

### 감사기도 데모만 보고 있었다

검토 루프는 진작 실제 앱으로 옮겼는데, 감사기 두 개(`ui-audit.mjs`, `visual-audit.mjs`)는
아직 `tools/demo.html` 을 열고 있었다. 데모는 마크업이 달라서, 감사기는

- **데모에만 있는 h1 누락을 12건 보고**하며 "총 이슈 종류: 1" 이라는 깨끗한 성적표를 냈고
- **사용자가 보는 화면은 한 번도 검사하지 않았다**

실제 앱으로 돌리자 첫 판에 4종 86건이 나왔다. 시드와 조작 코드는 `tools/seed.mjs` 로
빼서 세 도구가 같이 쓴다. 데모를 열던 코드가 다시 생기지 않도록 URL 자체를 그쪽에 두었다.

드러난 것과 고친 것:

- **대비 미달 (serious, 20건)** — 뿌리는 하나다. **`opacity` 로 흐리게 만든 것.**
  `.gradebar.is-zero` 는 줄 전체에 0.45, `.swatch.is-used` 는 0.35 를 걸었는데
  그러면 글자까지 흐려져 3.53:1, 2.51:1 로 떨어진다(기준 4.5). 흐리게 하는 건
  색이 있는 부분(홀드)만, 글자는 대비를 지키는 색으로 바꿨다. 아직 감사에 안 걸린
  `.graderow.is-retired` 도 같은 방식이라 함께 고쳤다
- **작은 글자 (56건)** — 칸의 개당 점수가 11px, 짐 목록의 '+4' 배지가 10px 이었다.
  둘 다 `--fs-min`(13px)으로. 칸은 좌우 여백을 0.15rem 으로 줄여 5명일 때도 들어가게 함
- **작은 탭 타겟 (6건)** — 세션 편집 스테퍼가 34x38. 44x44 로 키웠다.
  좁은 화면에서 보이는 줄이 6줄 → 5줄로 줄지만, 땀난 손으로 누르는 화면이라 이쪽을 택함
- **짐 목록 이름 시작점이 19px씩 흔들림** — 홀드 띠 폭을 내용에 맡겨 둔 탓.
  색 자료가 없는 짐은 84px, 있는 짐은 103px 이었다. 폭을 못 박았다
- **좁은 화면에서 홀드 띠가 이름 위로 46px 넘쳐 있었다** — 폭을 고정하면서 함께 해결
- **'+N' 배지가 거짓말을 하고 있었다** — 좁은 화면에서 `nth-child(n+4) { display: none }`
  으로 홀드를 3개만 보여 주면서, 배지는 자바스크립트가 센 `전체 − 5` 를 그대로 적었다.
  9단계 짐이 3개만 보이면서 '+4' 라고 쓰여 있었다. 실제로 감춰진 건 6개다.
  숨기는 규칙을 없애고 홀드 크기를 12px 로 줄여 다섯 개가 다 들어가게 했다

### 감사기 자체의 오탐 두 가지도 고쳤다

- **줄간격 규칙** — `scrollHeight > 글자크기 x 1.6` 으로 '여러 줄' 을 짐작했다.
  글자 한 자짜리 44px 버튼도 걸린다. `Range.getClientRects()` 로 실제 줄 수를 센다
- **가려짐 규칙** — 고정 바(탭바, 스티키 헤더, 모달 바닥)가 스크롤 중인 내용을 덮는 건
  설계다. 그걸 전부 올리니 164건이 쏟아져 진짜 문제가 묻혔다. 이제 세어서 넘기고
  건수를 출력한다. 조용히 거르면 '문제 없음' 으로 읽히기 때문이다.
  끝까지 스크롤해도 안 드러나는 경우는 `ui-audit` 의 covered 검사가 따로 잡는다

### 6차 수정 (자동 검사가 0건이 된 뒤, 눈으로 한 장씩)

자동 검사는 규칙에 적힌 것만 본다. 0건이 되고 나서 화면을 한 장씩 열어 보니
**규칙이 없는 종류**의 문제가 21건 나왔다.

**길 안내**
- 탭 화면 세 곳(기록·프로필·클라이밍장)에 **갈 곳 없는 '뒤로'** — 탭바가 이미 하는 일이고,
  같은 화면인데도 빈 상태에는 없어서 데이터 유무에 따라 나타났다 사라졌다 했다.
  진짜 하위 화면인 점수표에만 남긴다
- 화면 이동 버튼 네 곳이 **↗(앱 밖으로 나감)** 아이콘을 달고 있었다 → ›.
  ↗ 는 JSON 내보내기처럼 실제로 밖으로 나가는 동작에만 남긴다

**기록 화면**
- **짐 칩 110개** — 기록이 있는 곳은 한 곳뿐인데 나머지 109개를 누르면 빈 화면이 나온다.
  게다가 정작 지금 보고 있는 짐의 칩은 가로 스크롤 저 너머라 화면에 없었다.
  기록이 있는 곳만 남기고, 하나뿐이면 줄 자체를 없앤다. 지금 칩은 열 때 화면 안으로 민다
- **0인 단계의 홀드까지 45% 로 흐려** 노랑이 올리브가 되어 갈색과 헷갈렸다.
  이 앱에서 색은 곧 난이도다. 흐리게 할 것은 글자뿐이다

**점수표**
- 다이얼 세 칸이 각각 **128px 인데 내용은 70px** 이었다. `.dial` 의 `flex: 1 1 8rem` 은
  가로로 늘어놓는 `.fieldrow` 를 보고 쓴 값인데, `.dials` 는 세로 flex 라 같은 값이
  '높이 128px' 로 먹혔다. 175px 을 되찾자 점수표가 첫 화면 안으로 들어왔다

**위험한 동작**
- **`iconbtn--danger` 가 `.iconbtn` 과 완전히 같은 규칙이었다.** 이름만 위험하고 화면에는
  아무 차이가 없었다. 색을 새로 들이는 대신(색은 홀드 몫이다) 글리프로 나눈다.
  참가자 지우기는 **X**, 등급을 목록에서 빼기는 **−** (빼기는 되돌릴 수 있으므로 위험 표시 없음)
- `gradeRow` 에 **`aria-label` 이 두 번** 적혀 있었다. 뒤엣것만 살고 앞엣것은 죽은 코드
- **색 고르기가 직접 붙인 이름을 덮어썼다.** '흰색'을 '화이트'로 고쳐 둔 등급의 색만
  바꿔도 이름이 '파랑'으로 되돌아갔다. 팔레트 이름 그대로인 등급만 이름을 따라가게 함
- 색 고르기에 **지금 색 표시가 없었다** → 테두리로 표시
- **참가자 선택 모달이 막다른 길이었다.** 대결 격자는 이미 전원을 보여주므로 목록에서
  이름을 눌러도 화면이 그대로다. 누른 사람은 아무 일도 안 일어났다고 느낀다.
  세 호출부의 뜻이 모두 '만들기'라 바로 이름 입력으로 간다
- **현재 참가자를 지우면 다른 사람이 남아 있어도 기록 화면이 빈 상태**가 됐다 → 첫 사람으로 대체

**모달의 입력**
- 빈 칸으로 '추가'를 누르면 **조용히 아무 일도 일어나지 않았다.** 버튼이 고장 난 것처럼 보인다
  → 비어 있는 동안 못 누르게. `.btn:disabled` 규칙 자체가 없어서 함께 추가
- 그 disabled 를 `opacity: 0.4` 로 했더니 **글자와 배경이 같이 묽어져 '추가'가 안 읽혔다.**
  0인 단계·이미 쓴 색에서 배운 것과 같다 → 색을 갈아 끼운다
- **짐 추가 모달에 라벨이 없고** 자치구 placeholder 가 `강남구` 였다. 값이 이미 들어간 것처럼
  보인다. 짐 설정 화면은 이미 라벨 + `예: 강남구` 를 쓰고 있었다 → 같은 꼴로 맞춤

**한국어**
- **조사를 받침 없이 붙이고 있었다.** `${gym.name}은` → '강서클라이밍센터은',
  `${name}이 앞서고 있어요` → '지수이 앞서고 있어요'. 이름은 사용자가 넣는 값이라
  미리 알 수 없다 → `domain/text.js` 의 `josa()` 와 테스트 2개
- **합쇼체와 해요체가 섞여 있었다.** 아홉 곳, 그중 셋은 한 문장 쌍 안에서 섞였다
  ("...자료가 없습니다. ...넣어 주세요.") → 해요체로 통일

**짐 선택기**
- 112곳 목록에 **지금 어디인지 표시가 없었다.** 바꾸러 왔다가 길을 잃는다
  → '지금' 배지 + 열 때 그 줄을 검색창 바로 아래로
- `.pickerhead` 에 `gap` 선언이 두 번 (앞엣것은 죽은 코드)

**도구**
- `review.mjs` 가 `--only` 로 한 장만 찍을 때도 **폴더를 통째로 비웠다.**
  방금 지운 19장을 다시 찍느라 시간을 버린다. flow.mjs 와 같은 버그였다

### 6차 후반 — 코드에 남은 유령들

화면을 다 보고 나서 CSS 클래스와 코드를 맞춰 봤다. **화면 어디에도 안 붙는 규칙이 25개** 있었다.
스코어보드(`.board__*`), 난이도 카드(`.gcard*`), 하단 고정 총점(`.total*`), `.grades`, `.bar`,
`.dot`, `.holdcell`, `.chip__count`, `.levelrow*` — 전부 여러 번의 개편 전에 사라진 UI다.
`components.js` 의 `dot()` 도 아무도 부르지 않았다. app.css 가 1000줄에서 **866줄**로 줄었다.

죽은 CSS 는 그냥 용량 문제가 아니다. `iconbtn--danger` 처럼 **읽는 사람이 "이건 처리돼 있구나"
라고 믿게 만든다.** 실제로 감사기 두 개가 `.total__inner` 와 `.board__row` 를 가림 검사 대상으로
넣고 있었다. 몇 년 전부터 아무것도 안 걸리는 선택자였다.

같은 이유로 도구도 정리했다.

- `hold-test.mjs`, `verify-fixes.mjs` — `.gcard` 를 누르는 스크립트. 지금은 없는 UI다. 삭제
- `profile-test.mjs`, `ui-audit.mjs`, `seed.mjs` 의 죽은 선택자 정리

### e2e 페이지 두 개가 몇 개편 전 UI를 붙들고 있었다

`tools/e2e-record.html` 은 **단정 전부가 `.gcard` · `.board__row` · `.total__score`** 기준이었다.
브라우저로 직접 열어야만 결과가 보여서, 아무도 열지 않았고 아무도 몰랐다.

- 격자 UI 기준으로 다시 썼다 (14개 단정: 열 분리, 누적, 개당 점수 표기, 저장, 순위 배지, 길게 누르기)
- 기대값을 **`domain` 에서 계산**해 쓴다. 예전 테스트는 `750` 같은 상수를 박아 둬서
  기본 점수표가 바뀌자 엉뚱하게 실패하고 있었다 (`e2e-editor.html` 이 그 상태였다)
- `tools/e2e.mjs` 로 **헤드리스 자동 실행**. `npm run e2e`. 자동으로 돌지 않으면 또 썩는다

### 감사기가 여전히 1명짜리 화면만 보고 있었다

스크린샷은 `shot-grid.mjs` 로 1~5명을 찍게 했는데, **감사기 시드는 아직 1명**이었다.
순위 배지·좁아진 열·두 줄로 접힌 칸은 감사에 한 번도 오르지 않았다.
`ui-audit.mjs` 에 3명짜리 화면을 추가했다.

### 꺼진 서버 하나가 '실패 19건'으로 보였다

마지막 전체 점검에서 감사 두 개가 무더기로 실패했다.

```
dark·기록/통계 준비 실패: timeout: Runtime.evaluate          (11건)
light·짐 설정 준비 실패: SecurityError: localStorage ...      (8건)
```

앱이 망가진 것처럼 보이지만 원인은 하나였다. **개발 서버가 중간에 죽어 있었다.**
그 뒤로는 `Page.navigate` 가 아무 데도 가지 못해 페이지가 `about:blank` 에 머물렀고,
거기서 `localStorage` 를 읽으니 SecurityError, 평가를 걸면 타임아웃이 났다.
화면마다 증상이 달라 보인 탓에 원인이 하나라는 게 가려졌다.

- `tools/seed.mjs` 에 **서버 확인을 한 번** 넣었다. 안 떠 있으면 화면마다 다른 오류를
  쏟는 대신, 띄우는 명령까지 적어서 한 줄로 멈춘다
- `cdp.mjs` 의 `goto` 는 고정 대기 대신 **도착을 확인**한다. 바쁠 때 아직 `about:blank`
  인 채로 다음 줄이 실행되던 문제
- `send` 타임아웃 15초 → 60초. 기계가 바쁜 것만으로 멀쩡한 평가가 '실패'로 찍혔다

서버를 살리고 다시 돌리니 감사 두 개가 0건이 됐다. 딱 하나가 남았는데,
`폰·라이트·점수표` 에서 `Runtime.evaluate` 가 **60초를 넘겼다.** 이건 진짜였다.

시각 검사기는 글자가 있는 요소마다 `getComputedStyle` 을 부르고, 스크롤 조상을 타고
올라가며 또 부른다. 점수표는 16x11 표라 셀만 176개다. 조상까지 합치면 한 화면에서
`getComputedStyle` 을 수천 번 부르고 있었다. 한 번 돈 결과를 기억하게 하자
**5분 31초 → 실패 0건**으로 끝났다.

이번 라운드에서 세 번째로 확인한 같은 이야기다. **도구가 조용히 엉뚱한 것을 볼 때보다,
도구가 무엇을 못 보고 있는지 말해 줄 때 훨씬 빨리 고쳐진다.**

## 7차 — 남겨 뒀던 것을 마저

**`LV0` 표기.** 6차에서 "점수표 열이 좁아서" 유지했는데, 실제로 재 보니 `Lv.0`~`Lv.15` 가
넉넉히 들어갔다. 근거 없이 유지하고 있었다. 표기가 일곱 군데에 흩어져 있던 것도 함께 정리해
`domain/text.js` 의 `levelLabel()` 한 곳에서 정한다.

### 검토 루프가 못 보던 네 화면을 넣었다

기본 시드는 늘 같은 상태만 만들었다. 시드가 확인 배너를 눌러 치워 버리고, 색 없는 짐·즐겨찾기·
은퇴 등급은 애초에 만들어지지 않았다. 시드에 갈래(`gym`·`confirm`·`record`)를 주고 네 장면을
추가했다 (`21~25`). **넣자마자 진짜 버그가 하나 나왔다.**

- **별을 누를 때마다 모달이 한 겹씩 쌓였다.** `toggleFavorite` 가 목록을 갱신하려고
  `openGymPicker(ctx)` 를 다시 부르고 있었다. 세 번 누르면 모달 3개에 행 330개다.
  선택기가 스스로 다시 그리도록 바꾸고, 스크롤 위치도 지킨다.
  E2E 에 단정 네 개를 걸어 다시는 못 새게 했다
- **은퇴 등급의 홀드가 흐려져 노랑이 올리브로 보였다.** 6차에서 통계 화면에 같은 판단을
  내려 놓고 여기는 빠뜨렸다. 색은 데이터다. 흐리게 하는 건 글자뿐

### 난이도 자료가 없는 12곳 — 더 캘 것이 없다

spiri7 API 로 12곳을 다시 조회했다. 한 곳만 20단계가 돌아왔는데 **표준 V등급이었고,
전혀 다른 짐과 글자 하나까지 같은 목록**이었다. 색 체계를 등록하지 않은 짐에 API 가 주는
기본값이지 그 짐의 벽 세팅이 아니다. 이름·주소도 우리 기록과 달라 동일 시설인지 확실하지 않다.

그래서 데이터를 넣지 않았다. 대신 **다음 수집 때 이 기본값이 진짜 데이터로 들어오는 걸 막았다**
(`scrape-gyms.mjs` 의 `isDefaultVScale`). 안 막았으면 12곳에 없는 색이 생겼을 것이다.

12곳은 전부 지구력·리드·보드 중심 시설이다. **자료가 빠진 게 아니라 색을 안 쓰는 곳**이고,
앱은 이미 그렇게 말하고 있었다. 짐 선택기에서 통째로 비어 있던 홀드 칸은 점선 자리 표시로 채웠다.

### 7차 후속 — 고친 자리를 다시 보다가 둘 더

- **은퇴 표시가 사실상 없었다.** 홀드 흐림을 뺀 자리를 `--ink-3` 글자색으로 메웠는데,
  `--ink-2` 와 대비가 12.9:1 대 10.7:1 이라 눈으로는 구분되지 않는다(라이트에서 확인).
  신호가 `+` 아이콘 하나뿐이었다. 취소선을 긋는다 — 폭을 더 먹지 않고, 색을 들이지도 않는다
- **360px 에서 짐 이름이 전부 잘렸다.** 홀드 띠가 94px 을 먹어 이름 자리가 120px 만 남아
  다섯 줄이 모두 `강서클라이밍…` 이었다. 짐은 이름으로 고르는 것이지 색 미리보기로 고르는 게
  아니다. 좁은 화면에서는 띠를 이름 아래로 내린다. 한 줄이 65px 에서 110px 이 되어
  보이는 줄이 하나 줄지만, 이름이 온전한 쪽을 택했다

### 남긴 것

없다. 7차에서 마지막 하나(`LV0` 표기)까지 처리했다.

## 심각 (전부 수정 완료)

### S1. 점수표 우측 페이드가 강조 칸을 반쯤 지움
`dark/08`, `light/08`. 스크롤 컨테이너 가장자리 페이드가 배경색과 같아 일반 칸에서는 안 보이는데, 대비가 큰 대각선 강조 칸 위에서만 드러나 "칸이 찢어진 것"처럼 보인다. 스크롤 힌트가 아니라 버그로 읽힌다.

### S2. 점수표에 가로 스크롤 신호가 없음
난이도 11개 중 6열만 보이는데 화살표·스크롤바·부분 노출 어느 것도 없다. 빨강이 마지막 난이도라고 오해한다.

### S3. 좁은 화면에서 홀드가 잘려 난이도 색이 틀리게 보임
`small/09`, `small/10`. 360px에서 홀드 스트립이 강제로 잘려 4번째는 반쪽, 5번째는 통째로 사라진다. 오른쪽에 26px 빈 공간이 남아 있어 공간 부족이 아니라 폭 계산 오류로 보인다. **행의 존재 이유가 "그 짐의 난이도 색"인데 색 구성이 틀리게 전달된다.**

### S4. 짐 목록 하단이 글자 중간에서 하드 클리핑
`dark/09`, `dark/11`, `light/09`. 페이드 마스크가 적용되지 않았거나 너무 짧아 이름 글자가 그대로 잘린다. 잘리기 직전 픽셀 밝기가 정상 텍스트와 같다.

### S5. 스크롤 시 앞 행 셀 밑동이 스티키 헤더 아래로 삐져나옴
`small/02`. 왼쪽 열은 완전히 가리는데 오른쪽 열만 잘린 조각이 남아 헤더 아래 정체불명의 둥근 선이 그어진 것처럼 보인다. 좌우 열의 클리핑 기준이 다르다.

### S6. 세션 편집 목록이 반 줄에서 뭉텅 잘림
`small/15`. 스크롤 힌트가 전혀 없어 렌더링이 깨진 것처럼 보인다.

### S7. 세션 편집이 좁은 화면에서 사실상 못 씀
`small/15`. 11개 난이도 중 온전히 보이는 건 3개뿐. 날짜·레벨이 세로로 쌓이며 상단 절반을 먹고, 모달 위 여백이 화면의 14%다.

## 보통 (29건)

### 대결 격자
- 라이트에서 흐린 숫자 대비 3.2~3.45:1 (수정 완료)
- 참가자 1명일 때 좌우 균형 붕괴 — 가운데 135pt 빈 띠, 셀은 188×56pt에 한 자리 숫자만
- 탭바가 마지막 행을 반쯤 자름 (중간 스크롤 위치에서 항상)
- 상단 여백 64pt 과다 — 세로가 아쉬운 화면인데 한 행 분량을 버림

### 짐 선택기
- 모달 상단 127px 공백 vs 하단 16px — 위를 비우면서 목록은 행이 반토막
- 라이트에서 흰색·연회색 홀드가 흰 카드에 묻힘 (대비 1.08:1)
- 난이도 미등록 행의 왼쪽 200px가 통째로 비어 이가 빠져 보임. 왜 색이 없는지 설명도 없음
- 스크롤 시 검색창 아래 구분선이 5px 간격 두 줄로 겹침
- 빈 상태에 복구 버튼 없음, 결과 수 헤더도 사라져 일관성 깨짐
- 빈 상태에서 모달만 줄고 아래 410px가 텅 빔

### 짐 설정·점수표
- 팔레트 14개 중 11개가 이미 추가된 색인데 아무 표시 없음
- **같은 색인데 화면마다 홀드 모양이 다름** — 초록이 목록/팔레트/모달에서 타원·삼각형·덩어리
- 라이트 점수표 "흰" 열 머리 스와치가 흰 카드에 묻힘
- `—` 버튼이 "안 씀"이 아니라 "삭제"로 읽힘
- 배율 카드 414px 레이아웃 비대칭 (2열+1열), 설명이 두 줄로 깨져 "(1~5)"만 남음
- 색 고르기 모달에 어느 행을 바꾸는 중인지, 현재 색이 무엇인지 표시 없음

### 모달·첫실행
- 세션 편집 11번째 행 입력칸 윗변만 삐죽 튀어나옴
- 짐 추가의 두 입력칸 정렬이 다름 (왼쪽 vs 가운데)
- 구 입력칸이 플레이스홀더로 꽉 참
- 모달 간 일관성: 라벨 유무, 주 버튼 위치(오른쪽 vs 왼쪽)가 다름
- **말투 혼재** — 합쇼체와 해요체가 한 카드 안에서도 섞임
- 첫실행 대결 탭만 화면 제목이 없음
- **용어 혼용** — 짐 설정 / 클라이밍장 추가 / 클라이밍장 고르기 / 실내 클라이밍장

### 기록·통계·프로필
- 막대 트랙 회색이 두 종류 (0인 행 vs 값 있는 행의 남은 부분)
- 단계별 완등 카드 11행 중 8행이 0 — 가장 큰 요소가 가장 정보 없는 요소
- 세션 1회일 때 추이 그래프·대결 전적이 통째로 사라지고 안내 없음
- 숫자와 단위 baseline 어긋남 (단위가 6.5px 위로 뜸)
- 같은 화면 두 카드의 설명문 크기가 17% 차이
- 최근 세션 행에서 날짜와 점수의 위계 차이 과함, 값도 상단과 중복

## 사소 (26건)

- 짐 추가 플레이스홀더 대비 4.07:1 (기준 4.5)
- "그날의 레벨" 값 0이 실제값인지 플레이스홀더인지 불분명
- 점수표 모서리 칸 `LV \ 난이도`의 백슬래시가 두 줄로 쪼개져 안 읽힘
- 열 이름 한 글자 축약 시 흰/회, 갈/검 혼동
- 용어 혼용: 섹션 제목 "배율" vs 필드 "배수", 기준 점수는 배율이 아님
- 범위 안내 불균일 (기준 점수만 범위 없음)
- 홀드 아이콘 크기 편차 — 납작한 모양은 원형의 절반 이하 면적
- 프로필 삭제 `−` 아이콘 오른쪽 정렬선이 23px 어긋남
- `08월 24일` 앞자리 0은 한국어에서 어색
- 숙련도 슬라이더에 눈금 없음, LV0일 때 값과 축 라벨 중복
- `LV0` 표기보다 `Lv. 0` 또는 `레벨 0`이 자연스러움
- "참가자 +" 버튼이 추가인지 목록 열기인지 모호
- 빈 상태 제목의 물음표가 제각각, "깼는지"는 은어
- 세션 편집 개수 입력에 +/− 스테퍼 없음
- 그 외 문구 다듬기 다수

## 잘 된 점 (에이전트 공통 지적)

- **행 정렬이 픽셀 단위로 정확** — 홀드 중심·라벨 베이스라인·셀 중심이 1px 내로 맞음
- **탭 타깃 충분** — 360px에서도 셀 56pt로 기준(44pt) 초과
- **극단 색의 테마별 대응** — 흰색 홀드가 다크에서 꽉 찬 원, 라이트에서 테두리+옅은 채움으로 바뀜
- **대비 넉넉** — 라이트 최저 10.7:1, 다크 최저 9.9:1 (지적된 몇 곳 제외)
- **막대 길이가 값에 정확히 비례**
- **좌우 여백 일관** — 세 해상도에서 32/32
- **360px에서 텍스트가 접히면서도 카드 높이 유지**
- 스티키 헤더, 모달 하단 고정 바, 빈 상태 3종의 다음 행동 버튼
