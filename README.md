# 클라이밍 점수

클라이밍장에서 완등한 문제를 색깔 단위로 기록하고, **그 날 친구들과 점수로 겨루는** 앱.

빌드 없는 정적 사이트입니다. 런타임 의존성이 없고, `index.html`을 열면 그대로 돕니다.

## 실행

```bash
python3 -m http.server 8080     # 또는 npm run serve
open http://localhost:8080
```

`file://`로 직접 열면 ES 모듈과 시드 `fetch`가 막히니 서버로 띄우세요.

## 어떻게 쓰나

1. **클라이밍장 고르기** — 서울 실내 113곳이 들어 있습니다. 구 칩으로 좁히거나 이름으로 찾고, 없으면 직접 추가합니다. ★를 누르면 다음부터 자동 선택됩니다.
2. **색 등급을 안 쓰는 암장** — 14곳은 지구력·리드 중심이라 색 등급이 없습니다. 목록에 "지구력 중심"으로 표시됩니다.
3. **난이도 색 확인** — 98곳은 색 체계가 미리 들어 있습니다. 스피릿 등급 DB에서 가져왔고 블로그 후기 4건과 교차 검증했지만, 암장은 세팅을 바꾸므로 **미검증 초기값**으로 취급합니다. 배너에서 확인하거나 고치세요.
4. **내 숙련도 설정** — 프로필 화면에서 슬라이더로 정합니다. 지금 편하게 깨는 단계를 고르면 됩니다. 짐이 바뀌어도 그대로 적용됩니다.
5. **기록** — 난이도 카드를 탭하면 +1, 길게 누르면 −1. 하단에 오늘 점수가 실시간으로 뜹니다.
6. **대결** — 참가자를 추가하면 스코어보드에 나란히 뜨고 순위가 실시간으로 바뀝니다.

## 점수

내 레벨(L)과 문제 난이도 단계(d)의 차이로 정해집니다.

```
diff = d - L
diff >= 0  →  기준점수 × 1.5^diff
diff <  0  →  기준점수 × 0.5^(-diff)
```

|      | 1단계 | 2단계 | 3단계 | 4단계 | 5단계 |
|------|------|------|------|------|------|
| LV0  | 100  | 150  | 225  | 338  | 506  |
| LV1  | 50   | 100  | 150  | 225  | 338  |
| LV2  | 25   | 50   | 100  | 150  | 225  |

대각선(내 레벨 = 문제 난이도)이 항상 기준 점수입니다. 고수가 쉬운 문제를 잔뜩 깨서 점수를 쌓는 걸 막고, 초보의 첫 상급 완등을 제대로 칩니다. 배율과 개별 칸은 점수표 화면에서 고칠 수 있습니다.

**숙련도를 올려도 지난 점수는 변하지 않습니다.** 세션마다 기록 시점 레벨을 스냅샷으로 저장하기 때문입니다. 다만 오늘 기록은 아직 진행 중이므로 새 레벨을 따라갑니다.

## 오프라인

서비스워커가 앱 껍데기를 캐시하므로 신호가 없어도 뜹니다. 암장은 지하가 많습니다.
홈 화면에 추가하면 앱처럼 실행됩니다 (`manifest.webmanifest`).

기록은 원래 브라우저 안에만 있으므로 오프라인에서도 그대로 쌓입니다.

## 난이도 표시

색만으로 구분하면 색각이상자는 쓸 수 없습니다. 그래서 **색과 모양을 함께** 씁니다. 실제 클라이밍 홀드 8종(저그·슬로퍼·핀치·크림프·포켓·엣지·볼륨·언더클링)을 실루엣으로 만들어 난이도 순서마다 다른 모양을 배정합니다.

외곽선은 색 자체의 밝기로 정합니다. 테마 대비색 하나로 고정하면 흰색은 라이트에서, 검정은 다크에서 배경에 묻힙니다(실측 1.08:1).

## 구조

```
index.html
src/
  domain/     점수·집계·순위. 순수 함수, DOM도 저장소도 모른다
  storage/    저장 계약과 localStorage 구현
  ui/         화면
  styles/     디자인 토큰 (라이트/다크 2셋)
data/
  gyms.seed.json   서울 실내 113곳
tools/        검증용 페이지 (앱 코드 아님)
```

서버를 붙일 때는 `src/storage/api.js`를 추가하고 `src/app.js`의 어댑터 한 줄만 바꾸면 됩니다.

## 검토 루프

자동 검사는 자기가 아는 규칙만 본다. 규칙에 없는 추함은 통과시킨다.
그래서 **마지막 판정은 눈으로** 한다. 화면이 수십 개라 한 장씩 열면 감당이 안 되므로
한 장으로 합쳐서 훑고, 이상한 칸만 원본으로 확대해서 본다.

```bash
npm run review          # 전 화면·모달 22종을 한 장의 컨택트 시트로  → tools/shots/_sheet.png
npm run review:light    # 라이트 테마
npm run review:small    # 360x640 좁은 화면
npm run flow            # 상호작용 흐름 7종을 스텝별 스트립으로      → tools/flows/_all.png
npm run flow 완등       # 특정 흐름만
```

`flow`는 "누르면 어떻게 되는가"를 본다. 탭할 때마다 점수가 오르는지, 순위가 바뀌는지,
모달이 제대로 닫히는지는 정지 화면으로는 드러나지 않는다.

### 왜 이렇게까지 하는가

이전에 자동 검사가 "0건"이라고 해서 넘어갔다가 놓친 것들이 있다. 원인은 넷이었다.

| 원인 | 대책 |
|---|---|
| 서버가 `Cache-Control`을 안 보내 고쳐도 브라우저는 옛 화면을 렌더 | `tools/dev-server.py` (no-store) |
| 검사용 브라우저가 프로필을 공유해 옛 페이지를 검사 | 실행마다 프로필·포트 분리 + CDP 캐시 끄기 |
| 뷰포트 하나만 검사 (문제는 좁은 화면에서만 발생) | `review:small`, 감사기 뷰포트 3종 |
| `getBoundingClientRect`로 클리핑 여부를 *추정* | `document.elementFromPoint`로 브라우저에 직접 질의 |

## 테스트

```bash
npm test                      # 도메인 로직 19개
```

```bash
npm run scrape                # 암장 목록·난이도 재수집 (tools/cache에 캐시)
npm run audit:ui              # UI 자동 감사 — 겹침·잘림·대비·글자크기·터치타겟
npm run audit:a11y            # axe-core 접근성 감사 (agent-browser 필요)
```

`audit:ui`는 전 화면 × 다크/라이트 × 스크롤 위치 3단계를 돌며 다음을 검사합니다.

| 분류 | 규칙 |
|---|---|
| 겹침 | 텍스트끼리 겹침 / 고정 바가 콘텐츠를 덮음 / 반투명 바 아래 글자 비침 |
| 잘림 | `scrollWidth > clientWidth`인데 ellipsis 없음 / 부모 밖 넘침 |
| 대비 | axe-core WCAG 2.1 AA |
| 가독성 | 12px 미만 글자 / 44px 미만 터치 타겟 / 1.3 미만 줄간격 |

사용자 관점 QA 결과는 [`dogfood-output/report.md`](dogfood-output/report.md)에 있습니다.

브라우저 동작은 `tools/`의 페이지로도 확인합니다.

```bash
# 시나리오 데이터가 채워진 데모
open "http://localhost:8080/tools/demo.html"
open "http://localhost:8080/tools/demo.html?theme=light&route=stats"

# 상호작용 E2E (콘솔 대신 페이지 하단에 결과가 찍힘)
open "http://localhost:8080/tools/e2e-record.html"
open "http://localhost:8080/tools/e2e-editor.html"
```

`demo.html` 파라미터: `theme=light`, `route=stats|profile|gym|scoreTable|picker`, `gym=<이름 일부>`
