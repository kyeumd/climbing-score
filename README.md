# 클라이밍 점수

클라이밍장에서 완등한 문제를 색깔 단위로 기록하고, **그 날 친구들과 점수로 겨루는** 앱.

빌드 없는 정적 사이트입니다. 런타임 의존성이 없고, `index.html`을 열면 그대로 돕니다.

## 실행

```bash
python3 -m http.server 8080     # 또는 npm run serve
open http://localhost:8080
```

`file://`로 직접 열면 ES 모듈과 시드 `fetch`가 막히니 서버로 띄우세요.

## 어떻게 쓰나

1. **클라이밍장 고르기** — 서울 실내 112곳이 들어 있습니다. 구 칩으로 좁히거나 이름으로 찾고, 없으면 직접 추가합니다. ★를 누르면 다음부터 자동 선택됩니다.
2. **색 등급을 안 쓰는 암장** — 12곳은 지구력·리드 중심이라 색 등급이 없습니다. 목록에 "지구력 중심"으로 표시됩니다.
3. **난이도 색 확인** — 100곳은 색 체계가 미리 들어 있습니다. 스피릿 등급 DB에서 가져왔고 블로그 후기 4건과 교차 검증했지만, 암장은 세팅을 바꾸므로 **미검증 초기값**으로 취급합니다. 배너에서 확인하거나 고치세요.
4. **내 숙련도 설정** — 프로필 화면에서 슬라이더로 정합니다. 지금 편하게 깨는 단계를 고르면 됩니다. 짐이 바뀌어도 그대로 적용됩니다.
5. **기록** — 난이도 카드를 탭하면 +1, 길게 누르면 −1. 하단에 오늘 점수가 실시간으로 뜹니다.
6. **대결** — 참가자를 추가하면 스코어보드에 나란히 뜨고 순위가 실시간으로 바뀝니다.

## 점수

내 레벨(L)과 문제 난이도 단계(d)의 차이로 정해집니다.

```
diff = d - L
diff >= 0  →  기준점수 × 1.5^diff
diff <  0  →  기준점수 × 0.5^(-diff)
```

|      | 1단계 | 2단계 | 3단계 | 4단계 | 5단계 |
|------|------|------|------|------|------|
| LV0  | 100  | 150  | 225  | 338  | 506  |
| LV1  | 50   | 100  | 150  | 225  | 338  |
| LV2  | 25   | 50   | 100  | 150  | 225  |

대각선(내 레벨 = 문제 난이도)이 항상 기준 점수입니다. 고수가 쉬운 문제를 잔뜩 깨서 점수를 쌓는 걸 막고, 초보의 첫 상급 완등을 제대로 칩니다. 배율과 개별 칸은 점수표 화면에서 고칠 수 있습니다.

**숙련도를 올려도 지난 점수는 변하지 않습니다.** 세션마다 기록 시점 레벨을 스냅샷으로 저장하기 때문입니다. 다만 오늘 기록은 아직 진행 중이므로 새 레벨을 따라갑니다.

## 함께 보기 (선택)

`src/config.js` 의 `DATABASE_URL` 이 비어 있으면 기록은 이 브라우저에만 쌓입니다.
Firebase Realtime Database 주소를 넣으면 **방 코드를 아는 사람끼리 같은 화면을 실시간으로**
봅니다. 한 명이 완등을 누르면 다른 사람 화면의 점수가 새로고침 없이 오릅니다.

SDK 는 붙이지 않습니다. 우리가 쓰는 건 "값 하나 쓰고, 바뀌면 알려 줘" 둘뿐이라
REST 와 `EventSource` 로 충분하고, 그래야 런타임 의존성 0 이 유지됩니다.

```
읽기   GET    <db>/rooms/<코드>.json
쓰기   PUT    <db>/rooms/<코드>/sessions/<id>.json
구독   EventSource(<db>/rooms/<코드>.json)
```

**방 코드가 곧 비밀번호입니다.** 계정이 없으므로 코드를 아는 사람은 누구나 그 방을
읽고 씁니다. 그래서 코드는 30자 알파벳에서 16자를 뽑고, 받아 적을 때 반드시 틀리는
`0 O 1 I L` 은 알파벳에서 뺐습니다. 코드는 앱 데이터와 다른 열쇠에 저장해
내보내기 JSON 에 섞여 나가지 않게 합니다.

`firebase.rules.json` 을 콘솔의 규칙 탭에 붙여 넣으세요. 코드 길이를 요구하고,
방 목록 자체는 읽을 수 없게 막습니다.

무엇을 방에 올리는지는 나눠 두었습니다.

| | |
|---|---|
| 올린다 | 사람, 세션, 손으로 만진 짐 설정 |
| 안 올린다 | 짐 목록 시드 112곳 (83KB) |

시드는 모두에게 같은 붙박이 자료입니다. 방에 두면 앱을 열 때마다 스트림 첫 응답으로
통째로 내려옵니다.

**친구 초대는 링크로 합니다.** 코드는 16자라 말로 넘기기 어렵고, 짧게 만들면 자물쇠가
사라집니다. `#` 뒤에 코드를 붙이므로 서버 접속 기록에 남지 않고, 들어온 뒤에는 주소창에서
지웁니다. 링크가 막힌 상황을 위해 코드 직접 입력도 접이칸 뒤에 남겨 두었습니다.

**끌 수 있습니다.** 프로필 화면의 `함께 보기 끄기`. 검사 도구도 같은 스위치를 씁니다 —
안 그러면 앱을 띄우는 것만으로 진짜 방이 하나씩 생깁니다.

```bash
npm run fake-db     # Firebase 를 흉내 내는 로컬 서버 (검증 전용)
npm run sync        # 브라우저 둘로 실시간 동기화를 검증 (18개 단정)
npm run check:fb    # 진짜 Firebase 에 대고 규칙·스트림 확인
```

`npm run sync` 는 진짜 주소가 없어도 됩니다. 가짜 서버가 같은 REST·SSE 규약으로
답하므로 앱 코드는 상대가 진짜인지 모릅니다.

## 오프라인

서비스워커가 앱 껍데기를 캐시하므로 신호가 없어도 뜹니다. 암장은 지하가 많습니다.
홈 화면에 추가하면 앱처럼 실행됩니다 (`manifest.webmanifest`).

기록은 원래 브라우저 안에만 있으므로 오프라인에서도 그대로 쌓입니다.

## 난이도 표시

색만으로 구분하면 색각이상자는 쓸 수 없습니다. 그래서 **색과 모양을 함께** 씁니다. 실제 클라이밍 홀드 8종(저그·슬로퍼·핀치·크림프·포켓·엣지·볼륨·언더클링)을 실루엣으로 만들어 난이도 순서마다 다른 모양을 배정합니다.

외곽선은 색 자체의 밝기로 정합니다. 테마 대비색 하나로 고정하면 흰색은 라이트에서, 검정은 다크에서 배경에 묻힙니다(실측 1.08:1).

## 구조

```
index.html
src/
  config.js   서버 주소 한 곳. 비어 있으면 이 브라우저에만 저장한다
  domain/     점수·집계·순위. 순수 함수, DOM도 저장소도 모른다
  storage/    저장 계약, localStorage 구현, Firebase 동기화
  ui/         화면
  styles/     디자인 토큰 (라이트/다크 2셋)
data/
  gyms.seed.json   서울 실내 112곳
tools/        검증용 페이지 (앱 코드 아님)
```

저장 계약(`storage/adapter.js`)은 **동기**입니다. `loadAll` 은 화면을 다시 그릴 때마다
불리므로, 비동기로 바꾸면 호출부 스무 곳이 함께 흔들립니다. 그래서 동기화 어댑터도
동기를 지킵니다 — 읽기는 캐시가 즉시 답하고, 서버로 보내는 일만 뒤에서 합니다.
부팅에서 방에 붙는 한 줄만 `await` 입니다.

## 검토 루프

자동 검사는 자기가 아는 규칙만 본다. 규칙에 없는 추함은 통과시킨다.
그래서 **마지막 판정은 눈으로** 한다. 화면이 수십 개라 한 장씩 열면 감당이 안 되므로
한 장으로 합쳐서 훑고, 이상한 칸만 원본으로 확대해서 본다.

```bash
npm run review          # 전 화면·모달 25종 캡처                     → tools/shots/dark/
npm run review:light    # 라이트 테마
npm run review:small    # 360x640 좁은 화면
npm run review:grid     # 참가자 1~5명일 때의 입력 격자             → tools/shots/grid-dark/
npm run flow            # 상호작용 흐름 7종을 스텝별 스트립으로      → tools/flows/_all.png
npm run flow 완등       # 특정 흐름만
```

`flow`는 "누르면 어떻게 되는가"를 본다. 탭할 때마다 점수가 오르는지, 순위가 바뀌는지,
모달이 제대로 닫히는지는 정지 화면으로는 드러나지 않는다.

### 왜 이렇게까지 하는가

이전에 자동 검사가 "0건"이라고 해서 넘어갔다가 놓친 것들이 있다.
전부 **도구가 엉뚱한 것을 보고 있었다**는 한 가지 이야기다.

| 원인 | 대책 |
|---|---|
| 서버가 `Cache-Control`을 안 보내 고쳐도 브라우저는 옛 화면을 렌더 | `tools/dev-server.py` (no-store) |
| 검사용 브라우저가 프로필을 공유해 옛 페이지를 검사 | 실행마다 프로필 분리 + CDP 캐시 끄기 |
| 스크립트가 던지면 헤드리스 크롬이 살아남아, 다음 실행이 **좀비의 탭에 붙어** 남의 화면을 검사 | `--remote-debugging-port=0` 으로 크롬이 포트를 고르게 하고, `exit`·`SIGINT`·예외에서 전부 정리 |
| 감사기가 `tools/demo.html` 을 열어, 데모에만 있는 문제를 보고하고 **실제 앱은 한 번도 안 봄** | 시드·조작 코드를 `tools/seed.mjs` 로 모아 세 도구가 실제 앱을 누른다 |
| 시드가 늘 참가자 1명이라 **여럿일 때의 격자를 검토 루프가 못 봄** | `tools/shot-grid.mjs` 로 1~5명을 각각, 감사기에도 3명 화면 추가 |
| 시드가 늘 같은 상태만 만들어 **확인 배너·색 없는 짐·즐겨찾기·은퇴 등급을 한 번도 안 봄** | 시드에 갈래(`gym`·`confirm`·`record`)를 주고 장면 5개 추가. 넣자마자 모달이 겹겹이 쌓이는 버그가 나왔다 |
| 죽은 CSS·죽은 선택자가 "처리돼 있다"는 인상을 줌 (`iconbtn--danger` 는 아무 효과도 없었다) | 클래스와 코드를 대조해 25개 제거, 감사기 선택자도 정리 |
| e2e 페이지가 사라진 UI를 단정 (열어 봐야만 알 수 있음) | `npm run e2e` 로 헤드리스 자동 실행 |
| **개발 서버가 죽으면** 화면마다 다른 오류가 쏟아져 앱 문제로 보임 (실제로 19건) | `seed.mjs` 가 시작할 때 한 번 확인하고, 안 되면 띄우는 명령과 함께 멈춘다 |
| 탐색 후 고정 대기 → 바쁠 때 `about:blank` 에서 다음 줄이 실행됨 | `goto` 가 도착을 확인한다 |
| 뷰포트 하나만 검사 (문제는 좁은 화면에서만 발생) | `review:small`, 감사기 뷰포트 3종 |
| `getBoundingClientRect`로 클리핑 여부를 *추정* | `document.elementFromPoint`로 브라우저에 직접 질의 |
| 규칙이 오탐을 쏟아 내 진짜가 묻힘 (고정 바 가림 164건, 한 글자 버튼의 줄간격) | 고정 바 가림은 세어서 넘기고 **건수를 출력**, 줄 수는 `Range` 로 실측 |

## 테스트

```bash
npm test                      # 도메인 로직 28개
npm run e2e                   # 페이지 E2E — 기록 흐름·세션 수정 (헤드리스, 20개 단정)
```

`e2e` 는 반드시 자동으로 돌린다. 브라우저로 직접 열어야만 결과가 보이던 시절에는
아무도 열지 않았고, 몇 번의 UI 개편 전에 사라진 클래스를 붙들고 조용히 실패한 채 남아 있었다.
기대 점수는 상수로 박지 않고 `domain` 에서 계산한다.

```bash
npm run scrape                # 암장 목록·난이도 재수집 (tools/cache에 캐시)
npm run audit:ui              # UI 자동 감사 — 겹침·잘림·대비·글자크기·터치타겟
npm run audit:a11y            # axe-core 접근성 감사 (agent-browser 필요)
```

`audit:ui`는 전 화면 × 다크/라이트 × 스크롤 위치 3단계를 돌며 다음을 검사합니다.

| 분류 | 규칙 |
|---|---|
| 겹침 | 텍스트끼리 겹침 / 고정 바가 콘텐츠를 덮음 / 반투명 바 아래 글자 비침 |
| 잘림 | `scrollWidth > clientWidth`인데 ellipsis 없음 / 부모 밖 넘침 |
| 대비 | axe-core WCAG 2.1 AA |
| 가독성 | 12px 미만 글자 / 44px 미만 터치 타겟 / 1.3 미만 줄간격 |

사용자 관점 QA 결과는 [`dogfood-output/report.md`](dogfood-output/report.md)에 있습니다.

브라우저 동작은 `tools/`의 페이지로도 확인합니다.

```bash
# 상호작용 E2E (콘솔 대신 페이지 하단에 결과가 찍힘)
open "http://localhost:8080/tools/e2e-record.html"
open "http://localhost:8080/tools/e2e-editor.html"

# 눈으로 볼 데모. 자동 검사에는 쓰지 않는다 (실제 앱과 마크업이 다르다)
open "http://localhost:8080/tools/demo.html?theme=light&route=stats"
```

`demo.html` 파라미터: `theme=light`, `route=stats|profile|gym|scoreTable|picker`, `gym=<이름 일부>`

## 데이터

기록은 **이 브라우저의 localStorage에만** 있습니다. 캐시를 지우면 사라지니 프로필 화면에서 가끔 JSON으로 내보내 두세요.

짐 목록과 난이도 체계는 [스피릿(spiri7)](https://spiri7.com/)에서 가져왔고, [climblife](https://climblife.co.kr/)와 [OpenStreetMap](https://www.openstreetmap.org/copyright)(ODbL)으로 보강했습니다. 목록은 완전하지 않습니다. 인공암벽장업은 체육시설업 등록 대상이 아니라 정부 통계 자체가 없습니다.

설계 근거와 조사 기록은 [`docs/superpowers/specs/2026-08-20-climbing-score-design.md`](docs/superpowers/specs/2026-08-20-climbing-score-design.md)에 있습니다.
