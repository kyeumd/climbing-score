## ISSUE-001 [높음] 기록 탭 빈 상태에 빠져나갈 길이 없다

**증상**: 신규 사용자가 첫 화면에서 순서를 건너뛰고 [기록] 탭을 누르면 "프로필과 클라이밍장을 먼저 골라 주세요."라는 문장만 뜨고 **아무 버튼도 없다.** 사용자는 어디로 가야 하는지 알 수 없다.

**재현**
1. localStorage를 비우고 앱 실행
2. 하단 탭에서 [기록] 선택
3. 안내 문구만 있고 액션 버튼 없음 → `screenshots/issue-001.png`

**원인**: 빈 상태 화면이 안내만 하고 해결 경로를 주지 않았다.

**수정**: 상황에 맞는 버튼을 넣었다. 짐이 없으면 "클라이밍장 고르기", 프로필이 없으면 "프로필 만들기"가 뜬다.

## ISSUE-002 [높음] 짐 설정 탭이 다른 화면 위에 모달만 띄운다

**증상**: 짐을 고르지 않은 상태에서 [짐 설정] 탭을 누르면 **배경은 직전 화면(프로필) 그대로**이고 그 위에 짐 선택 모달만 뜬다. 탭 활성 표시도 [프로필]에 남아 있다. 모달을 닫으면 프로필 화면이라 "짐 설정에 못 갔다"는 인상을 준다.

**재현**
1. localStorage를 비우고 앱 실행
2. [프로필] 탭 → [짐 설정] 탭
3. 제목은 "프로필", 위에 모달만 → `screenshots/issue-002.png`

**원인**: 탭 핸들러가 짐이 없을 때 라우팅 없이 모달만 열었다.

**수정**: 짐이 없어도 짐 설정 화면으로 먼저 진입하고, 그 화면 안에서 "클라이밍장 고르기"를 안내한다.

## ISSUE-003 [치명] 상태가 바뀔 때마다 화면이 맨 위로 튕긴다

**증상**: 난이도 색을 하나 추가하면 **스크롤이 맨 위로 돌아간다.** 팔레트는 화면 아래쪽에 있으므로 색을 9개 등록하려면 9번 다시 스크롤해야 한다. 대결 화면에서 난이도 카드를 탭할 때도 마찬가지라, **암장에서 완등을 기록할 때마다 화면이 튀어 사실상 사용할 수 없다.**

**재현**
1. 짐 설정 → 아래로 스크롤(위치 520)
2. 색 스와치 하나 탭
3. 스크롤 위치 0으로 리셋 → `screenshots/issue-004.png`

**측정**: 탭 전 `scrollY=520` → 탭 후 `scrollY=0`

**원인**: `render()`가 매번 DOM 전체를 교체하고 무조건 `window.scrollTo(0)`을 호출했다.

**수정**: 라우트가 실제로 바뀔 때만 맨 위로 올리고, 같은 화면 안의 상태 갱신에서는 스크롤 위치를 복원한다.

**검증**: 탭 전 420 → 탭 후 420 (점수는 925 → 975로 정상 반영)

## ISSUE-004 [치명] 입력 중 포커스가 날아간다

**증상**: 등급 이름을 고치면 입력칸에서 포커스가 `<body>`로 튕겨 나간다. 등급 9개 이름을 연달아 고치려면 매번 다시 탭해야 한다.

**재현**
1. 짐 설정 → 등급 이름 입력칸에 포커스
2. 값을 바꾸고 change 발생
3. `document.activeElement`가 `BODY`

**원인**: ISSUE-003과 같은 뿌리 — 전체 재렌더로 원래 DOM 노드가 사라진다.

**수정**: 입력칸에 안정적인 `data-fkey`를 부여하고, 재렌더 후 같은 키를 찾아 포커스와 커서 위치까지 복원한다.

**검증**: 편집 후 `INPUT.graderow__label`에 포커스 유지, 값도 반영

## ISSUE-005 [중간] 점수표 배율에 0을 넣으면 점수 체계가 무너진다

**증상**: "어려울 때 ×"에 `0`을 입력하면 대각선을 뺀 **모든 칸이 1점**이 된다(첫 행: 100, 1, 1, 1, 1, 1). 난이도 구분이 사라져 앱의 존재 이유가 없어진다.

**원인**: 배율에 `v >= 0` 검사만 있었다. 0과 1 미만은 의미상 성립하지 않는다 — 어려운 문제가 오히려 낮은 점수가 된다.

**수정**: 의미 있는 범위를 정의하고 입력·계산 양쪽에서 가둔다.
- 기준 점수 1 ~ 100,000
- 어려울 때 × 1.0 ~ 5.0
- 쉬울 때 × 0.05 ~ 1.0

범위를 벗어난 입력은 조용히 삼키지 않고 가장 가까운 유효값으로 되돌리며 화면에도 반영한다. 회귀 테스트 2개 추가.

## ISSUE-006 [낮음] 날짜 필드가 "연도 연도"로 중복해서 읽힌다 — 수정 불가

**증상**: 스크린리더가 날짜 입력을 "연도 연도", "월 월", "일 일"로 읽는다.

**조사**: 같은 페이지에 세 가지 방식을 넣고 접근성 트리를 비교했다.

| 라벨 방식 | 읽히는 이름 |
|---|---|
| 라벨 없음 | "연도" / "월" / "일" |
| `<label>`로 감싸기 | "연도 연도" |
| `aria-label` | "연도 연도" |

**결론**: Chrome이 `<input type=date>`의 각 세그먼트 이름 앞에 라벨을 덧붙이는 **브라우저 동작**이다. 라벨을 붙이는 어떤 방법으로도 피할 수 없다.

**판단**: 수정하지 않는다. 라벨을 없애면 중복은 사라지지만 이 날짜가 무엇을 뜻하는지 맥락이 사라져 더 나쁘다. 중복은 어색할 뿐 정보 손실이 아니며 axe 위반도 아니다.
